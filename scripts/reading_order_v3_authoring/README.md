# Reading Order v3 clean-room authoring contract

**SAFE FOR ISOLATED AUTHOR TO READ**

This directory is the complete candidate-independent authoring interface for a future
Reading Order v3 corpus. An isolated author can create all human-authored corpus content,
seal it, and validate schema/integrity/authoring coverage without opening historical
corpora, historical validators, candidate diagnostics, calibration material, qualification
outputs, or forensic evidence.

Passing this validator is not qualification, reachability evidence, or candidate-quality
evidence. The tooling never imports or executes the Reading Order candidate and never
scores candidate output.

## Exact safe author-facing surface

The isolated author may read only these repository files plus the new corpus being authored:

- `scripts/reading_order_v3_authoring/README.md`
- `scripts/reading_order_v3_authoring/__init__.py`
- `scripts/reading_order_v3_authoring/__main__.py`
- `scripts/reading_order_v3_authoring/canonical.py`
- `scripts/reading_order_v3_authoring/contracts.py`
- `scripts/reading_order_v3_authoring/validate.py`
- `<NEW_CORPUS_ROOT>/**`

The isolated author **must not open** repository tests, historical Reading Order validators,
prior held-out assets, calibration packages, qualification packages/workflows or outputs,
candidate diagnostics, or forensic evidence. In particular, do not open:

- `tests/reading_order_v3_authoring/`
- `scripts/reading_order_v2/validate_corpus.py`
- `assets/reading-order-v2/heldout*/`
- `assets/reading-order-post-v2/heldout*/`
- `scripts/reading_order_post_v2_calibration/`
- `tests/reading_order_post_v2_calibration/`
- `scripts/reading_order_post_v2_qualification/`
- Reading Order qualification workflow outputs or forensic-evidence directories

Those paths are listed only as isolation boundaries. Their contents and observed constraints
are intentionally not reproduced here.

## Safe commands

The author needs only:

```text
python -m scripts.reading_order_v3_authoring build-manifest <NEW_CORPUS_ROOT>
python -m scripts.reading_order_v3_authoring validate <NEW_CORPUS_ROOT>
```

`build-manifest` validates the complete authoring contract before it writes a manifest.
`validate` requires the sealed manifest to match the recomputed canonical bytes exactly.

## Corpus layout and roles

`<NEW_CORPUS_ROOT>` contains exactly:

- `corpus-design.json`;
- one source artifact, image, input JSON, and annotation JSON for every declared page;
- `manifest.json`, generated by this tooling.

Role paths are declared by each page in `corpus-design.json`. They must be unique,
normalized POSIX-relative paths. Absolute paths, `..`, backslashes, drive-qualified paths,
leaf symlinks and symlinked ancestor directories are rejected. All resolved sealed paths
must remain beneath the real corpus root.

The **source** role is opaque provenance/artifact bytes. It is hash/inventory bound but is
not parsed, imported, or executed by clean-room validation or the future qualification
input mapping. The kit imposes no source-file format.

## Identity

`corpusId`, `version`, and `pageId` are new author-chosen identifiers. They are not tied to
a historical corpus identity, page count, or page-number pattern.

- `corpusId` and `version`: 1-128 characters, starting with an ASCII letter/digit and then
  using ASCII letters/digits plus `.`, `_`, `+`, or `-`.
- `pageId`: 1-128 characters, starting with an ASCII letter/digit and then using ASCII
  letters/digits plus `.`, `_`, or `-`.
- page IDs are unique within the design.
- `regionId` is a separate contract: any nonempty unique string on its page. It is not
  restricted to the page-ID syntax.

## Authorship provenance declaration

`corpus-design.json` must declare:

```json
{
  "authorshipBoundary": "isolated-candidate-independent-v3",
  "provenanceDeclaration": {
    "priorHeldoutEvidenceInspected": false,
    "calibrationOutputsInspected": false,
    "candidateDiagnosticsInspected": false,
    "candidateExecuted": false,
    "qualificationExecuted": false,
    "annotationsAdaptedToCandidateOutput": false
  }
}
```

This is an explicit author declaration. The validator checks its exact presence/value; it
cannot independently prove the declaration's truth.

## Frozen declassified design minima

These are normative methodology requirements, not observed historical evidence. The sealed
corpus must satisfy all of them:

- `minimumPageCount = 24`
- `minimumQualificationPairs = 120`
- `minimumScoredRegions = 96`
- `minimumCombinedMechanismPages = 4`
- `minimumIntentionalFallbackPages = 3`
- `minimumCleanControlPages = 6`

No actual prior corpus counts, assignments, page IDs, geometry, or outputs are encoded.

## Positive authoring families and dedicated coverage

The eight positive families are:

- `c1-boundary-positive`
- `c2-gutter-bridge`
- `c2-ambiguous-overlap-bridge`
- `c2-pair-precedence-slot`
- `c3-positive-recovery`
- `b1-horizontal`
- `b1-vertical`
- `b1-mixed-orientation`

Every family requires at least one dedicated page. A page is dedicated only when its
`positiveFamilies` contains exactly one positive family and `primaryPositiveFamily` names
that family. A page carrying the `combined-c1-c2-c3-b1` qualification slice is a combined
page and cannot satisfy a dedicated positive-family requirement. Combined pages remain
separately required by the frozen design minimum.

Every `qualificationPairs[].slices` array uses only the following declassified vocabulary.
The pair/page minima are enforced before seal:

| `c1-boundary-positive` | 10 | 4 |
| `c1-near-boundary-negative` | 8 | 4 |
| `c2-gutter-bridge` | 8 | 3 |

There are no pair-local C3-negative category slices in this author-facing vocabulary.
Generic C3 rejection is page metadata described below.

## Design-role compatibility and `layoutTags`

`layoutTags` is **not an author field** in the v3 clean-room annotation. No later reviewer or
runner may add human-authored layout judgments after seal.

The three frozen design roles are derived mechanically from qualification-pair slice
membership:

- a page is a combined-mechanism page iff at least one authored pair has
  `combined-c1-c2-c3-b1`;
- a page is an intentional-fallback page iff at least one authored pair has
  `intentional-fallback`;
- a page is a clean-control page iff at least one authored pair has `clean-control`.

The validator applies the design page minima to these derived page sets. This preserves the
normative design requirements while avoiding historical layout-tag vocabulary and any
second round of human judgment.

## Generic C3 rejection

C3 negative authoring is page-level only. Set `authoringCoverage.c3Rejection: true` on a
page intended as a generic C3 rejection witness.

- witness name: `c3_rejection_pages`;
- `c3_rejection_pages >= 8` unique pages;
- a page counts at most once regardless of qualification-pair count;
- there is no pair-local C3-negative slice requirement;
- no candidate diagnostic reason or causal rejection category is authored.

The future internal qualification compatibility layer must carry this generic page marker
mechanically into v3 arm/evidence selection. It must not fabricate a category-specific C3
label.

## Input schema and deterministic runtime semantics

Schema version: `reading-order-v3-authoring-input-v1`.

```json
{
  "schemaVersion": "reading-order-v3-authoring-input-v1",
  "pageId": "page-alpha",
  "width": 800,
  "height": 600,
  "regions": [
    {
      "regionId": "region A",
      "sourceIndex": 0,
      "lines": [[[10, 10], [20, 10], [20, 20], [10, 20]]],
      "angle": 0.0
    },
    {
      "regionId": "region B",
      "sourceIndex": 1,
      "lines": [[[30, 10], [40, 10], [40, 20], [30, 20]]],
      "angle": 0.0
    }
  ]
}
```

A qualification page requires at least two regions. Width/height are arbitrary positive
integers; no historical image size is required. Region IDs and source indexes are unique,
source indexes are contiguous from zero, every line is a four-point integer quadrilateral
inside the page bounds, and `angle` is finite.

The frozen clean-room serialization -> canonical runtime-input mapping is structural only:

- `pageId` -> identical `pageId`;
- `width` -> identical `width`;
- `height` -> identical `height`;
- each `regionId` -> identical `regionId`;
- each `sourceIndex` -> identical `sourceIndex`;
- `lines` -> identical integer point tuples;
- `angle` -> identical finite numeric value;
- runtime region tuple order -> ascending `sourceIndex`.

The compatibility step performs no renaming, geometry inference, threshold logic,
annotation-dependent transformation, candidate access, or page-ID reinterpretation. It is
fully deterministic and requires no human judgment after seal.

## Annotation schema

Schema version: `reading-order-v3-authoring-annotation-v1`.

```json
{
  "schemaVersion": "reading-order-v3-authoring-annotation-v1",
  "pageId": "page-alpha",
  "readingOrder": ["region A", "region B"],
  "unscoredRegionIds": [],
  "qualificationPairs": [
    {
      "id": "pair-alpha",
      "earlier": "region A",
      "later": "region B",
      "slices": ["clean-control"]
    }
  ]
}
```

`readingOrder` and `unscoredRegionIds` are duplicate-free, disjoint, and together must equal
the exact input-region inventory. `readingOrder` is the scored-region sequence.

Every qualification pair must have a nonempty page-unique `id`; `(earlier, later)` must be
unique on the page; both endpoints must be scored; `earlier` must precede `later` in
`readingOrder`; and `slices` must be nonempty, duplicate-free, lexicographically sorted, and
limited to the author-facing vocabulary above. Qualification pairs are sealed authorial
content and may not be added or reinterpreted after seal.

## Strict sealed PNG contract

Each image must be a complete non-interlaced 8-bit RGB truecolor PNG. The validator checks
the byte stream without relying on permissive image-mode conversion:

- exact PNG signature;
- IHDR first, unique, correctly sized, with positive dimensions;
- bit depth 8, truecolor RGB color type 2, compression/filter method 0, interlace 0;
- CRC correctness for every chunk and rejection of unknown critical chunks;
- at least one IDAT and one valid terminal IEND;
- complete IDAT zlib stream with EOF and no unused/unconsumed compressed bytes;
- exact decompressed scanline byte count `(1 + width * 3) * height`;
- valid PNG filter byte 0-4 for every row;
- no trailing bytes after IEND;
- PNG dimensions exactly equal clean-room input dimensions.

Malformed/decompression failures are fail-closed. No arbitrary scientific dimension or
geometry limits are added. Extremely large locally authored PNGs can still amplify local
memory/CPU during validation; that residual resource-amplification risk is LOW/nonblocking
and should be controlled operationally rather than by inventing corpus-science thresholds.

## Manifest and exact inventory

Schema version: `reading-order-v3-authoring-manifest-v1`.

Do not hand-maintain the manifest. `build-manifest` binds corpus identity/version,
`corpus-design.json`, every page role path/hash, and exact inventory records containing
byte length plus SHA-256. Inventory ordering is deterministic.

`manifest.json` is never followed through a symlink. Writing uses a same-directory temporary
regular file and atomic replacement. Validation recomputes the manifest and requires the
on-disk bytes to equal the canonical JSON bytes exactly. A semantically equivalent but
noncanonical JSON serialization is invalid.

Any missing/extra file, changed bytes, stale hash, role-path change, symlinked sealed path,
or noncanonical manifest invalidates the corpus.
